# Windows + NVIDIA GPU variant of requirements.txt. Same pins as requirements.txt
# except onnxruntime -> onnxruntime-gpu, PLUS the pip-installable CUDA/cuDNN runtime
# wheels needed for onnxruntime-gpu's CUDAExecutionProvider to actually load on
# Windows -- not just the toolkit-installer route requirements-gpu.txt's own header
# comment mentions, this is the lighter "no admin install, no separate CUDA Toolkit"
# alternative verified working directly on this machine (see logfile.md's "Current
# status" section for the exact test and versions).
#
# onnxruntime-gpu and plain onnxruntime both import as the `onnxruntime` module and
# conflict if both installed -- exactly one per environment, same rule as
# requirements-gpu.txt.
#
# IMPORTANT -- pip install alone is NOT enough. These nvidia-*-cu12 wheels place their
# DLLs under .venv\Lib\site-packages\nvidia\<component>\bin\, which is NOT on PATH by
# default. Verified directly: onnxruntime.get_available_providers() lists
# CUDAExecutionProvider regardless (it reports what the wheel was compiled to support,
# not what's actually loadable), but a real InferenceSession(providers=[...]) silently
# falls back to CPU until those bin\ directories are added to PATH (or registered via
# os.add_dll_directory() -- not currently done anywhere in mirage's own startup code).
# Until that's wired in, prepend these to PATH before running `python -m mirage` /
# `python -m mirage.api`:
#   .venv\Lib\site-packages\nvidia\cublas\bin
#   .venv\Lib\site-packages\nvidia\cuda_nvrtc\bin
#   .venv\Lib\site-packages\nvidia\cuda_runtime\bin
#   .venv\Lib\site-packages\nvidia\cudnn\bin
#   .venv\Lib\site-packages\nvidia\cufft\bin
#   .venv\Lib\site-packages\nvidia\nvjitlink\bin
# See logfile.md for the follow-up: wiring this into mirage's own startup instead of
# requiring it be set manually every time.
